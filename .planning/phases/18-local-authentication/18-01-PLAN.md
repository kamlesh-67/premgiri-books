## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → POST /api/v1/auth/login | Untrusted email + password from browser form |
| HTTP Cookie → middleware / API routes | auth-token JWT from browser — verified but not inherently trusted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01 | Information Disclosure | login route | mitigate | Return identical error message "Incorrect email or password" for both user-not-found and wrong-password (ASVS V2.1.1 user enumeration prevention) |
| T-18-02 | Tampering | JWT signing | mitigate | HS256 with JWT_SECRET >= 32 bytes; validate JWT_SECRET presence at startup; verifyJWT catches all tamper/expiry cases and returns null |
| T-18-03 | Tampering | httpOnly cookie | mitigate | auth-token cookie set with httpOnly:true, sameSite:'lax' — not accessible to JS; lax prevents cross-origin POST submissions |
| T-18-04 | Elevation of Privilege | JWT payload | mitigate | JWT payload includes companyId; every API route (Plan 02) must filter DB queries by session.companyId — multi-tenant isolation preserved per AUTH-04 |
| T-18-05 | Spoofing | JWT_SECRET absent in Electron | mitigate | node startup check: if JWT_SECRET undefined or length < 32 throw clear error before serving any request |
| T-18-SC | Tampering | pnpm add jose | mitigate | jose is VERIFIED [OK] in RESEARCH.md Package Legitimacy Audit (8yr old package, npm registry confirmed) — no checkpoint needed |
</threat_model>
