## 1. How Claude Code Works — Mental Model

```
You (prompt) → Claude Code → Reads files → Writes code → Runs commands → Shows result
                    ↑
              CLAUDE.md (persistent context loaded every session)
              MCPs     (give Claude tools: DB, GitHub, browser, APIs)
              Skills   (pre-written instruction sets for complex tasks)
```

**The 3 levers for efficiency:**

| Lever | What It Does | Token Impact |
|---|---|---|
| **CLAUDE.md** | Tells Claude your stack, rules, file structure — once | Saves 50-80% repeat context |
| **MCPs** | Give Claude direct tool access (DB, GitHub, Figma) | Replaces manual copy-paste |
| **Skills** | Pre-written expert instructions for specific tasks | Replaces explaining same thing 10x |

### 📄 Skill 1: `gst-engine.md`

Create at: `.claude/skills/gst-engine.md`

````markdown
# Skill: GST Calculator for India (2024)

## Rules — Always Follow
- CGST + SGST applies when seller state == buyer state (intra-state)
- IGST applies when seller state != buyer state (inter-state)  
- GST rates in India: 0%, 5%, 12%, 18%, 28%
- Every invoice line must carry: hsn_code, qty, unit, taxable_value, gst_rate, cgst, sgst, igst
- Round off GST to 2 decimal places (Indian standard)
- Place of Supply (POS) determines CGST/SGST vs IGST
- For B2C invoices above ₹2.5 lakh: treat as B2CL in GSTR-1
- Reverse Charge Mechanism (RCM): buyer pays GST, not supplier

## GSTR-1 JSON Structure (mandatory fields)
```typescript
interface GSTR1Payload {
  gstin: string;
  fp: string;       // filing period: "112024" = Nov 2024
  b2b: B2BInvoice[];
  b2cl: B2CLInvoice[];
  b2cs: B2CSummary[];
  nil: NilRatedSupply;
  exp: ExportInvoice[];
  hsn: HSNSummary[];
}
```

## Tax Calculation Function Pattern
```typescript
function calculateGST(taxableValue: number, rate: number, isInterState: boolean) {
  const total = parseFloat(((taxableValue * rate) / 100).toFixed(2));
  if (isInterState) return { igst: total, cgst: 0, sgst: 0 };
  const half = parseFloat((total / 2).toFixed(2));
  return { igst: 0, cgst: half, sgst: total - half }; // handles rounding
}
```

## HSN Codes for Common Items (reference)
- 8471: Computers / Laptops → 18%
- 6403: Footwear → 18%
- 0901: Coffee → 5%
- 2106: Food preparations → 12%
- 9403: Furniture → 18%
- 9999: Services (use SAC codes)
````

Create at: `.claude/skills/voucher-engine.md`

````markdown
# Skill: Double-Entry Voucher Engine

## Core Rule — Non-Negotiable
Every voucher MUST have: SUM(debit entries) == SUM(credit entries)
If not balanced → reject with error, never save.

## Voucher Number Format
`{TYPE_CODE}/{FY}/{SEQUENCE}`
Example: `INV/2024-25/00001`, `PUR/2024-25/00034`, `REC/2024-25/00012`
- FY: if date >= April 1 → current year, else current year - 1
- Sequence: zero-padded 5 digits, resets each FY, per voucher type

## Accounting Rules
| Voucher | Debit | Credit |
|---|---|---|
| Sales Invoice | Debtor/Cash | Sales + GST Payable |
| Purchase Invoice | Purchase + Input GST | Creditor/Cash |
| Receipt | Cash/Bank | Debtor |
| Payment | Creditor | Cash/Bank |
| Credit Note | Sales Return | Debtor |
| Debit Note | Creditor | Purchase Return |

## Status Machine
draft → posted → (cancelled)
- Draft: saved but not in books
- Posted: affects ledger balances, stock, GST
- Cancelled: reversed, audit logged, never deleted

## Prisma Transaction Pattern (always use this)
```typescript
const result = await prisma.$transaction(async (tx) => {
  const voucher = await tx.vouchers.create({ data: voucherData });
  await tx.voucherEntries.createMany({ data: entries });
  await tx.voucherItems.createMany({ data: items });
  await tx.gstTransactions.create({ data: gstData });
  await tx.auditLogs.create({ data: auditEntry });
  return voucher;
});
```
````

### 📄 Skill 3: `report-engine.md`

Create at: `.claude/skills/report-engine.md`

````markdown
# Skill: Financial Report Engine

## Balance Sheet Structure (Indian Format)
```
EQUITY & LIABILITIES          |  ASSETS
Capital Account               |  Fixed Assets
  Add: Net Profit             |  Current Assets
  Less: Drawings              |    Cash & Bank
Loans (Liability)             |    Sundry Debtors
Current Liabilities           |    Closing Stock
  Sundry Creditors            |  Loans (Asset)
  GST Payable                 |  Misc Expenditure
```

## P&L Structure (Indian Format)
```
INCOME                        |  EXPENSES
Gross Sales                   |  Opening Stock
  Less: Returns               |  + Purchases
= Net Sales                   |  - Closing Stock
Other Income                  |  = Cost of Goods Sold
                              |  Operating Expenses
                              |  Depreciation
= NET PROFIT / LOSS
```

## Key SQL Pattern: Running Balance for Ledger Statement
```sql
SELECT 
  v.date,
  v.voucher_no,
  v.narration,
  CASE WHEN ve.dr_cr = 'dr' THEN ve.amount ELSE 0 END as debit,
  CASE WHEN ve.dr_cr = 'cr' THEN ve.amount ELSE 0 END as credit,
  SUM(CASE WHEN ve.dr_cr = 'dr' THEN ve.amount ELSE -ve.amount END) 
    OVER (ORDER BY v.date, v.created_at) as running_balance
FROM voucher_entries ve
JOIN vouchers v ON v.id = ve.voucher_id
WHERE ve.ledger_id = $1
  AND v.date BETWEEN $2 AND $3
  AND v.company_id = $4
  AND v.status = 'posted'
ORDER BY v.date, v.created_at;
```

## Number Formatting — Indian System
- Use: ₹1,23,45,678.00 (not ₹12,345,678.00)
- Lakhs = 1,00,000 | Crores = 1,00,00,000
- Always show Dr/Cr suffix on ledger balances
````

Create at: `.claude/skills/nextjs-conventions.md`

````markdown
# Skill: Next.js 16 Conventions for Premgiri-books

## File Naming
- Pages: `page.tsx` (React Server Component by default)
- Layouts: `layout.tsx`
- Loading: `loading.tsx` (Suspense boundary)
- Error: `error.tsx` (Error boundary, must be 'use client')
- API routes: `route.ts`

## Server vs Client Components
- DEFAULT to Server Components — add 'use client' only when needed
- Use 'use client' for: forms, keyboard shortcuts, modals, charts, real-time data
- Data fetching in Server Components: direct async/await, no useEffect
- Data fetching in Client Components: React Query (TanStack Query)

## API Route Pattern (always use this structure)
```typescript
// app/api/v1/vouchers/route.ts
import { NextRequest, NextResponse } from 'next/server';
import { getServerSession } from 'next-auth';
import { z } from 'zod';

export async function POST(req: NextRequest) {
  try {
    const session = await getServerSession(authOptions);
    if (!session) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });
    
    const body = await req.json();
    const validated = VoucherSchema.parse(body); // Zod validation
    
    const result = await VoucherEngine.postVoucher(validated, session.companyId);
    return NextResponse.json(result, { status: 201 });
  } catch (e) {
    if (e instanceof z.ZodError) return NextResponse.json({ errors: e.errors }, { status: 400 });
    return NextResponse.json({ error: 'Server error' }, { status: 500 });
  }
}
```

## Multi-tenancy Rule
EVERY Prisma query must include `where: { companyId: session.companyId }`
Never skip this. Add it even on single-record lookups.

## shadcn/ui Components to Use
- Forms: Form, Input, Select, DatePicker, Textarea
- Layout: Sheet (side panel), Dialog (modal), Tabs
- Data: Table, DataTable (with TanStack)
- Feedback: Toast (Sonner), Alert, Badge
- Navigation: Sidebar (use shadcn sidebar component)
````

### 📄 Skill 5: `prisma-patterns.md`

````markdown
# Skill: Prisma ORM Patterns for Accounting App

## Always Use Decimal for Money
```prisma
amount      Decimal  @db.Decimal(15, 2)
gst_rate    Decimal  @db.Decimal(5, 2)
```
NEVER use Float for money. Float causes rounding errors in accounting.

## Soft Delete Pattern (never hard delete financial records)
```prisma
model vouchers {
  id         String   @id @default(uuid())
  status     Status   @default(DRAFT)  // DRAFT | POSTED | CANCELLED
  deleted_at DateTime?
  // Add to every WHERE: { deleted_at: null }
}
```

## Audit Log — Add to Every Mutation
```typescript
await tx.auditLogs.create({
  data: {
    companyId,
    userId: session.userId,
    entity: 'voucher',
    entityId: voucher.id,
    action: 'CREATE', // CREATE | UPDATE | DELETE | CANCEL
    oldValue: null,
    newValue: JSON.stringify(voucher),
    ipAddress: req.headers.get('x-forwarded-for') ?? 'unknown',
  }
});
```

## Financial Year Helper
```typescript
export function getFY(date: Date): string {
  const year = date.getFullYear();
  const month = date.getMonth() + 1; // 1-indexed
  return month >= 4 ? `${year}-${String(year + 1).slice(2)}` 
                    : `${year - 1}-${String(year).slice(2)}`;
  // April 2024 → "2024-25", January 2024 → "2023-24"
}
```
````

## 5. Token Saving Strategies

### 🎯 The Golden Rules

```
1. WRITE CLAUDE.md → saves 50-80% context tokens
2. USE /compact regularly → compresses conversation history  
3. SCOPE your prompts → "only edit lib/services/GSTCalculator.ts"
4. USE MCP postgres → Claude reads DB directly, no copy-paste schema
5. BREAK big features → 1 prompt = 1 function, not 1 prompt = 1 module
6. USE --resume → continue session without re-explaining context
```

### 📊 Token Cost by Task Type

| Task Type | Token Cost | Strategy |
|---|---|---|
| Generate new file from scratch | Low | Good — Claude has full control |
| Edit existing large file | High | Scope with line numbers: "edit lines 45-90" |
| Explain the whole codebase | Very High | Use MCP filesystem instead |
| Debug with full error stack | Medium | Paste only the relevant error + file |
| Write tests | Low | "Write tests for this function: [paste function]" |
| Review entire PR | Very High | Use GitHub MCP instead |

### 🗜️ Context Compression Commands

```bash
# In Claude Code terminal:
/compact                    # Compress history, keep context
/clear                      # Full reset — use when switching phases
/resume                     # Resume last session
claude --continue           # Continue from last checkpoint
```
